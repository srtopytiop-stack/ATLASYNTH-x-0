# سياسة الأمان وحدود التشغيل

## الثوابت

- `TRADING_ENABLED=false`
- `LIVE_TRADING_ENABLED=false`
- `PUBLIC_MARKET_DATA_ONLY=true`
- `TRADING_TYPE=spot`
- لا مفاتيح API خاصة بمنصة التداول.
- لا توجد routes لإرسال أو تعديل أو إلغاء أوامر البورصة.
- أي قرار بحثي يظل بحاجة إلى مراجعة بشرية.

## الأسرار

لا تودع `.env` أو رموز Telegram في المستودع. احتفظ بـ `.env.example` للمتغيرات الوهمية/القيم الافتراضية غير الحساسة فقط، واستعمل secrets الخاصة بمنصة الاستضافة. لا تمرر أسرار البيئة إلى كود تجارب المستخدم أو إلى الواجهة الأمامية.

إذا تسرب token، اعتبره مخترقًا وألغِه/دوّره فورًا في الجهة المالكة. حذف القيمة من آخر commit لا يزيلها من سجل Git.

## HTTP وبيانات السوق

- استعمل endpoint العام لبيانات السوق فقط.
- حد زمني للطلبات، ومعالجة أخطاء HTTP، وحدود عدد الرموز والشموع.
- تحقّق من ردود API كمدخلات غير موثوقة.
- لا تسمح لمدخل symbol أو interval أن يتحول إلى URL حرّ أو طلب لعنوان اختاره المستخدم.
- في النشر، حدد CORS للأصول الموثوقة بدل wildcard في بيئة إنتاج.
- لا تعيد رسائل أخطاء حساسة أو إعدادات بيئية إلى العميل.

## الواجهة

- لا تُخزن الأسرار في `VITE_*`؛ متغيرات Vite التي تبدأ بـ VITE قد تصبح مرئية في كود العميل.
- لا تزعم الواجهة وجود صفقة أو بيانات حية عند انقطاع الاتصال.
- اعرض توقيت البيانات وحالة التحليل، وعلّم بيانات الاختبار الاصطناعية بوضوح.
- تعامل مع محتوى المصدر الخارجي كنص غير موثوق، لا تنفذ HTML عشوائيًا.

## تنفيذ التجارب

Web Worker أو عملية فرعية ليست وحدها sandbox أمنيًا قويًا. لا تنفذ كودًا عدائيًا داخل عملية API الأساسية، ولا تعرض الأسرار أو ملفات الخادم لمدخلات التجارب. تشغيل كود غير موثوق يستلزم عزلًا على مستوى نظام التشغيل/حاوية، وحدود ذاكرة ووقت وشبكة وملفات وصلاحيات، ومراجعة أمنية مستقلة.

## Telegram

الإشعارات اختيارية ومعطلة افتراضيًا. الإشعار نص بحثي وليس أمرًا. لا ترسل أي رسالة إلا بعد تقرير مرشح يمر عبر شروط التطبيق. حمى token وchat ID خارج ملفات المصدر، وراجع محتوى الرسالة حتى لا توحي بضمان الأرباح.

## النشر

- اجعل API غير مكشوفة للعالم بلا ضوابط إذا احتوت لاحقًا بيانات مستخدم خاصة.
- أضف rate limiting ومراقبة وحماية DoS عند النشر العام.
- استخدم HTTPS.
- راجع الاعتماديات ونقاط الضعف، وحدّثها عبر طلبات تغيير قابلة للمراجعة.
- استخدم صلاحيات GitHub الدنيا الضرورية؛ لا تضع tokens في workflows أو logs.
- اختبر إعدادات البيئة الفعلية قبل النشر.

## إبلاغ عن مشكلة أمنية

لا تنشر تفاصيل استغلال محتملة في issue عام. تواصل بشكل خاص مع مالك المستودع عبر قناة أمنية مناسبة، ووفّر خطوات إعادة الإنتاج وتأثيرًا مختصرًا دون إرفاق أسرار حقيقية.
